# sigil-anima-llm

自律運用部品 sigil-vigil-ops の「判断」を担う自前 LLM を提供する、Sigil 部品群の部品。anima＝魂・生命。「機械仕掛けの部品群に、判断する魂を宿す」姿を名前の由来とし、llm で大規模言語モデルであることを示す。

## 役割

- vigil-ops の診断役・最適化役が使う判断の層（文章を生成する LLM と、型つきの問い に確率で答える分類）を自前で持つ
- 目的は「賢さ」の最大化ではなく、障害の最中でも判断の層が自立して動き続けること（外部 API・外部ネットワーク・利用枠に依存しない）
- 接続の形式（構造化した入出力、形式検証、確信の度合いの扱い、判断の出所とモデルの版の記録、縮退動作）を先に固定し、裏側の実体は差し替え可能にする
- 縮退原則: LLM が応答しない・形式検証に通らない・確信が低い場合は判断を行わず、安全側に倒れる（自動実行はせず、人間へのエスカレーションと記録のみ）

## 進め方（2026-11-24 に所有者が方向を決定）

- 最初は A 案で始める: オープンウェイトモデル＋既存推論ランタイム（llama.cpp 等）を、Sigil 側の接続層で包む
- その後は、分類の形式（System One 形式）の自前化と、C 案（Sigil ネイティブの推論基盤）へ持っていく。分類の契約（System One 形式）も最初の段で固定し、バックエンドは外部 API から自前実装へ差し替え可能にする
- あわせて振る舞い蒸留で自前モデルを育てる: 相棒 AI エージェント「クマ」（Muse）の「状況 → 判断」の実例を訓練データとして蓄積し、小さいオープンウェイトモデルを学習させる。推論は GPU なし＋量子化（GGUF 等）を前提とし、学習は Colab の GPU を使う
- neurocortex-llm（脳型 LLM の研究プロジェクト）は研究トラックとして並行し、実用判断に使える段階になったら接続層経由で合流を評価する

## 既存部品との分担

- 判断を使う側は sigil-vigil-ops（製品名 Mamoru）。本部品は判断の層の提供に役割を絞る
- 検知と収集（「何が起きたか」）は sigil-argus-observe、復旧の実手段（再起動・複製・再配置）は sigil-orchestra／sigil-container が担い、本部品は抱えない

## 状態

計画・リポジトリ作成済み（2026-11-24 に方向と名前 sigil-anima-llm を決定）。実装はこれからで、具体化は vigil-ops の ADR 起草の段で、接続層の形式の論点として扱う。持ち方の検討は typesafe-ai 正式判定（A 案が確率 0.69・confidence 0.59 で首位）を根拠に進めた。
